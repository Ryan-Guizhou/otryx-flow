# ADR-002：服务独立 Schema + Outbox/Inbox

**状态：Proposed / 2026-10-23**

**背景**：Service A 持久化成功后，A→B RPC 可能超时/丢失回复，不能假定对端没执行。

**决策**：每个服务只写自己的 Schema；状态改变与 `outbox_event` 同一 DB 事务。重试投递携带 `eventId` 和自然幂等键；下游持久化 `inbox_dedup` 并在同一业务事务应用。不得在本地数据库事务中等待外部 RPC。

**结果**：事件至少一次投递，跨服务最终一致；必须建立未交付 Outbox、死信和对账告警。避免两端各自无限重试；合理退避、租约和人工处理入口。
